# 📌 Sequence Models & Transformers
> **Category:** Machine Learning & Natural Language Processing
> **Tags:** Deep Learning, NLP, RNN, LSTM, Seq2Seq, Transformers, Attention Mechanism

### Recurrent Neural Networks (RNN)
*   **The Concept:** Sequential processing with a running memory.
*   **Mechanism:** Processes data sequentially (word-by-word) rather than all at once. It maintains a hidden "memory" state that updates as it passes context from previous words to the next.
*   **Limitation:** Suffers from the "vanishing gradient" problem. It has poor short-term memory, meaning the mathematical signal from early words fades by the time it reaches the end of a long sentence.

### Long Short-Term Memory (LSTM)
*   **The Concept:** An advanced RNN equipped with a dedicated memory track and management gates.
*   **Mechanism:** Contains internal mathematical checkpoints (gates) that actively decide what past information to remember, what to forget, and what new context to add. 
*   **Impact:** Handled longer text sequences far better than standard RNNs and remained the industry standard for NLP until 2017.

### Sequence-to-Sequence (Seq2Seq)
*   **The Concept:** An architectural blueprint for transforming one sequence into another (e.g., machine translation).
*   **Mechanism:** Splits the task into two networks:
    *   **Encoder:** Reads the input sequence and compresses its meaning into a single, dense matrix called a **Context Vector**.
    *   **Decoder:** Unpacks the Context Vector to generate the output sequence.
*   **Limitation:** The Context Vector acts as an information bottleneck. Compressing long paragraphs into a single mathematical vector inevitably causes information loss.

### Self-Attention & Transformers
*   **The Concept:** Processing the whole picture at once instead of sequentially.
*   **Mechanism:** The core innovation behind the Transformer architecture (introduced in *Attention Is All You Need*). Instead of reading sequentially, it analyzes the entire sequence simultaneously and maps out the mathematical relationship (attention weight) between every single word and every other word in the text.
*   **Impact:** Eliminated the Context Vector bottleneck and the need for sequential processing, allowing for massive parallelization on GPUs. This enabled training on internet-scale datasets, powering modern LLMs like ChatGPT.

# 📌 Server Services, Ports, and Firewall Rules

> **Category:** Computer Networks  
> **Tags:** Networking, Servers, IP Address, Ports, Firewall, TCP/IP, Client-Server Architecture

### 1. What Is a Server?

A server is a computer or software system that provides services or resources to clients over a network.

Examples of clients include web browsers, mobile applications, and other servers.

A server may have a public IP address that allows it to be reached over the internet, or it may use a private IP address accessible only within a private network.

### 2. Multiple Services on a Server

A single server can run multiple network services simultaneously. Each service typically listens on a particular port.

| Service | Default Port | Purpose |
|---|---:|---|
| HTTP | 80 | Unencrypted web communication |
| HTTPS | 443 | Encrypted web communication |
| SSH | 22 | Remote server administration |
| PostgreSQL | 5432 | Database connections |

These are conventional port assignments. A service can be configured to use a different port.

**Important:** A port does not perform a task by itself. It identifies a network endpoint through which a particular service can receive traffic.

### 3. What Is a Port?

A port is a logical communication endpoint used by network protocols such as TCP and UDP.

When a client connects to a server, the destination is identified by an IP address and a port number.

Example:

`203.0.113.20:443`

- `203.0.113.20` identifies the destination IP address.
- `443` identifies the destination port.
- The service listening on port 443 handles the incoming connection.

The IP address identifies the network destination, while the port helps identify the intended service.

### 4. What Is a Firewall?

A firewall controls network traffic according to configured security rules.

Rules can specify:
- Source IP address: Where the connection originates.
- Destination IP address: Which machine receives the traffic.
- Destination port: Which service the client is trying to reach.
- Protocol: For example, TCP or UDP.
- Whether the traffic should be allowed or blocked.

A firewall may allow all source IP addresses to access a public website while restricting SSH and database access to specific machines.

### 5. Example: Firewall Rules

Suppose a server has a public IP address and runs three services.

| Port | Service | Firewall rule |
|---:|---|---|
| 443 | HTTPS web application | Allow connections from all source IPs |
| 22 | SSH | Allow only the office IP |
| 5432 | PostgreSQL | Allow only the backend server's IP |

In this configuration:
- Any client may attempt to access the HTTPS service.
- Only the permitted office IP may initiate an SSH connection.
- Only the permitted backend server may connect to PostgreSQL.

These rules govern network access, not necessarily application-level permissions.

### 6. How an Incoming Request Is Processed

The general flow is:

1. The client identifies the destination server using DNS or an IP address.
2. The client initiates a connection to the destination IP and port.
3. Network security controls, such as firewalls, evaluate whether the connection is allowed.
4. If allowed, the connection can reach the service listening on that port.
5. The service processes the request and may perform additional authentication and authorization checks.
6. The service sends a response if appropriate.

A connection can be allowed by the firewall but still fail if no service is listening on the port.

### 7. Important Distinctions

**IP address vs. port**

- An IP address identifies a network destination.
- A port identifies a network endpoint on that destination.

**Port vs. firewall rule**

- A port does not decide which source IPs are allowed.
- A firewall or another access-control mechanism defines those restrictions.

**Network access vs. application authorization**

- A firewall determines whether traffic can reach a service.
- The application determines whether a particular request or operation is permitted.

For example, a user may successfully connect to a website but still need to log in before accessing a private account.

### 8. Key Takeaway

A server can run multiple services, each listening on one or more ports. Firewall rules can restrict which source IP addresses are allowed to connect to specific ports. After a connection reaches the intended service, the application processes the request and applies its own authentication, authorization, and business logic.

**Remember:** IP address = destination, port = network endpoint, firewall = network access control, application logic = request handling and permissions.
