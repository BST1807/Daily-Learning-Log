# 📌 Sequence Models & Transformers

> **Category:** Machine Learning & Natural Language Processing
> **Tags:** Deep Learning, NLP, RNN, LSTM, Seq2Seq, Transformers, Attention Mechanism

### Recurrent Neural Networks (RNN)

- **The Concept:** Sequential processing with a running memory.
- **Mechanism:** Processes data sequentially (word by word) rather than all at once. It maintains a hidden state that carries information from previous words to subsequent words.
- **Limitation:** Standard RNNs can suffer from vanishing or exploding gradients, making it difficult to learn long-range dependencies in long sequences.

### Long Short-Term Memory (LSTM)

- **The Concept:** An advanced RNN equipped with a dedicated memory state and management gates.
- **Mechanism:** Uses gates to control what information to retain, forget, and add to its memory.
- **Impact:** LSTMs handle long-range dependencies better than standard RNNs, although they do not eliminate the problem entirely. They were widely used in NLP before Transformers became dominant.

### Sequence-to-Sequence (Seq2Seq)

- **The Concept:** An architectural approach for transforming one sequence into another, such as machine translation.
- **Mechanism:** Typically uses two components:
  - **Encoder:** Processes the input sequence and represents its information in encoded states.
  - **Decoder:** Uses the encoded information to generate the output sequence.
- **Limitation:** In the original encoder-decoder architecture, compressing the entire input into a single context vector creates an information bottleneck. Attention mechanisms help alleviate this limitation by allowing the decoder to access different encoder states.

### Self-Attention & Transformers

- **The Concept:** Allowing tokens to interact with other tokens in a sequence without relying on recurrent processing.
- **Mechanism:** Introduced in the Transformer architecture described in *Attention Is All You Need* (2017), self-attention calculates relationships between tokens using attention weights. This helps each token build a context-aware representation.
- **Impact:** Transformers enable parallel processing of input tokens during training, avoid the recurrent-processing bottleneck, and scale effectively on modern accelerators. They power modern large language models (LLMs), including ChatGPT.

### Important Clarifications

- Transformers process input tokens in parallel within a layer, but autoregressive generation typically produces output tokens sequentially.
- Self-attention does not inherently understand meaning; it learns useful token relationships from training data.
- Standard self-attention has computational and memory costs that grow approximately quadratically with sequence length.

# 📌 Server Services, Ports, and Firewall Rules

> **Category:** Computer Networks
> **Tags:** Networking, Servers, IP Address, Ports, Firewall, TCP/IP, Client-Server Architecture

### 1. What Is a Server?

A server is a computer or software system that provides services or resources to clients over a network.

Examples of clients include web browsers, mobile applications, and other servers.

A server may have a public IP address that makes it reachable over the internet, or a private IP address that is accessible within a private network.

A server does not always need its own public IP address. It can be accessed through a router, NAT gateway, reverse proxy, or load balancer with a public IP address.

### 2. Public IP vs. Private IP

- **Public IP address:** A globally routable address used for communication across the internet.
- **Private IP address:** An address used within private networks, such as home Wi-Fi or an organization's internal network.

Example:

- Laptop private IP: `192.168.1.10`
- Example public IP: `203.0.113.20`

**Note:** `203.0.113.20` is reserved for documentation and is not a real public server address.

### 3. Multiple Services on a Server

A single server can run multiple network services simultaneously. Each service typically listens on one or more ports.

| Service | Default Port | Purpose |
|---|---:|---|
| HTTP | 80 | Unencrypted web communication |
| HTTPS | 443 | Encrypted web communication |
| SSH | 22 | Remote server administration |
| PostgreSQL | 5432 | Database connections |

These are conventional port assignments. Services can be configured to use different ports.

**Important:** A port does not perform a task by itself. It identifies a network endpoint through which a service can receive traffic.

### 4. What Is a Port?

A port is a logical communication endpoint used by transport protocols such as TCP and UDP.

When a client connects to a server, the destination is identified by an IP address and a port number.

Example:

`203.0.113.20:443`

- `203.0.113.20` identifies the destination IP address.
- `443` identifies the destination port.
- The network stack directs traffic to the appropriate endpoint, where the listening service or proxy handles the connection.

A network connection also has a source IP address and source port. For TCP, the combination of source IP, source port, destination IP, and destination port helps distinguish connections.

### 5. What Is a Firewall?

A firewall controls network traffic according to configured security rules.

Rules can specify:

- **Source IP address:** Where the connection originates.
- **Destination IP address:** Which machine receives the traffic.
- **Destination port:** Which network endpoint the client is trying to reach.
- **Protocol:** For example, TCP or UDP.
- **Action:** Whether the traffic should be allowed or blocked.

A firewall may allow all source IP addresses to access a public website while restricting SSH and database access to specific machines.

### 6. Example: Firewall Rules

Suppose a server runs three services.

| Port | Service | Example Firewall Rule |
|---:|---|---|
| 443 | HTTPS web application | Allow connections from all source IPs |
| 22 | SSH | Allow only the office IP |
| 5432 | PostgreSQL | Allow only the backend server's IP |

In this configuration:

- Any source IP may attempt to connect to HTTPS.
- Only the permitted office IP may initiate an SSH connection.
- Only the permitted backend server may connect to PostgreSQL.

These rules control network access, not necessarily application-level permissions.

### 7. How an Incoming Request Is Processed

1. The client resolves the server's domain name using DNS, if necessary.
2. The client initiates a connection to the destination IP address and port.
3. Firewalls and other network controls evaluate whether the connection is allowed.
4. If permitted, the connection can reach the service listening on that endpoint.
5. The service processes the request and may perform authentication and authorization checks.
6. The service sends an appropriate response.

A connection can be allowed by the firewall but still fail if no service is listening, the server is unavailable, or another network issue occurs.

### 8. Network Access vs. Application Authorization

These are distinct security layers:

- **Firewall:** Determines whether network traffic can reach a service.
- **Authentication:** Verifies the identity of a user or client.
- **Authorization:** Determines which operations an authenticated user or client may perform.
- **Application logic:** Validates and processes the requested operation.

For example, a user may successfully connect to a website but still need to log in before accessing a private account.

### 9. Important Clarifications

- A server can run multiple services, and a service can listen on multiple ports.
- Multiple services can sometimes share a port through mechanisms such as a reverse proxy.
- A public IP makes a destination addressable over the internet, but firewalls and other network controls may restrict access.
- An allowed source IP does not automatically grant permission to perform every operation.
- A service must be running and listening on the relevant endpoint to accept connections.
- Firewall rules can also control outbound traffic, not just incoming connections.

### 10. Key Takeaways

- **IP address:** Identifies a network destination.
- **Port:** Identifies a network endpoint associated with a service.
- **Firewall:** Controls network traffic according to security rules.
- **Authentication:** Verifies identity.
- **Authorization:** Determines permitted actions.
- **Application logic:** Processes requests and enforces business rules.

A server can run multiple services, each listening on one or more ports. Firewall rules can restrict which source IP addresses may connect to particular ports. Once traffic reaches a service, the application applies its own validation, authentication, and authorization rules.
