# 📌 MLOps Tooling: Dependency Locking, Git Hygiene, Makefiles, and Code Quality
> **Category:** MLOps & System Engineering
> **Tags:** uv, requirements.in, git, makefile, ruff, black, linting, formatting

### 1. Modern Dependency Management with `uv`
To ensure environment reproducibility across production servers and different developers, dependencies must be strictly locked rather than just listed.

* **The Wishlist (`requirements.in`):** A high-level specification file containing only direct, top-level packages (e.g., `pandas`, `scikit-learn`). It excludes version numbers and helper libraries.
* **The Lockfile (`requirements.txt`):** An exhaustive, machine-generated receipt containing every exact package required, including **transitive dependencies** (the helpers that top-level packages rely on to function). Every package is pinned to a specific version (e.g., `numpy==1.26.0`).
* **`uv`:** A modern, incredibly fast package manager written in Rust that replaces standard `pip` and `pip-tools` for compiling and installing dependencies.

**Compilation Command:**
```bash
# Translates the .in wishlist into a strict .txt lockfile
uv pip compile requirements.in -o requirements.txt
```

### 2. Git Artifact Management (`.gitignore`)
If junk files (like `__pycache__`, `venv/`, `.env`, or `.pkl` model files) are accidentally committed to Git before a `.gitignore` exists, simply creating a `.gitignore` is not enough. Git will continue tracking them.

**Untracking Files (Without Deleting from Disk):**
You must remove them from Git's internal index (cache) first, then stage everything again so Git applies the new `.gitignore` rules.

```bash
# 1. Generate the .gitignore file
cat << 'EOF' > .gitignore
__pycache__/
*.pyc
venv/
.ipynb_checkpoints/
*.pkl
.env
EOF

# 2. Remove all files from Git's index but keep them on the hard drive
git rm -r --cached .

# 3. Restage files (Git will now ignore the artifacts listed in .gitignore)
git add .
git commit -m "chore: untrack local environment and cache files"
```

### 3. Workflow Automation with Makefiles
A `Makefile` acts as a universal control panel for complex terminal commands, heavily used in MLOps pipelines to standardize workflows.

* **Targets:** Named recipes (e.g., `setup`, `train`). Running `make train` in the terminal executes the commands nested under that target.
* **`.PHONY`:** A safety declaration telling Make that targets are action names, not physical files or folders on the disk (preventing conflicts if a folder named `test` exists next to a `test:` target).
* **Indentation Rule:** Make explicitly rejects spaces. Commands under a target **must** be indented with a real `Tab` character.
* **Constructive vs. Destructive Targets:** The `all` target runs constructive steps sequentially (e.g., `setup` -> `data` -> `train` -> `test`). Destructive targets like `clean` (which aggressively wipe caches and trained models) are kept separate to avoid accidental data deletion.

**Example Makefile Structure:**
```makefile
.PHONY: setup data train test clean all

all: setup data train test

setup:
	python3 -m venv mlops-venv/
	mlops-venv/bin/pip install -r requirements.txt

clean:
	find . -type d -name "__pycache__" -exec rm -rf {} +
	rm -rf .pytest_cache
	rm -rf models/*
```

### 4. Code Quality: Linting & Formatting (Ruff & Black)
Automated code quality tools are standard in modern pipelines to enforce consistency across teams. Configurations are unified inside the `pyproject.toml` file.

* **Black (The Formatter):** An uncompromising formatter that completely rewrites code to enforce strict visual styling (e.g., wrapping lines so they never exceed 120 characters).
* **Ruff (The Linter):** A blazing-fast linter that catches logical bugs and enforces stylistic rules without changing the underlying logic of the code. We configure it using specific category codes:
  * `F` (Pyflakes): Catches logical bugs (e.g., unused variables).
  * `E` / `W` (Pycodestyle): Catches stylistic errors and warnings.
  * `I` (Isort): Automatically sorts and groups `import` statements alphabetically.

**Configuration (`pyproject.toml`):**
```toml
[tool.black]
line-length = 120

[tool.ruff]
line-length = 120

[tool.ruff.lint]
select = ["E", "F", "W", "I"]
```

**Execution Commands:**
```bash
# Format code visually
black src/

# Lint code and automatically fix violations (like sorting imports)
ruff check --fix src/

# Verify passage (should exit silently with status 0)
ruff check src/
black --check src/
```
