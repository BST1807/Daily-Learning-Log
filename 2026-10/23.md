# Bloom Filter

**Date:** 2026-10-23
**Category:** Data Structures / System Design

## Overview
A **Bloom Filter** is a space-efficient, probabilistic data structure used to test whether an element is a member of a set. It prioritizes memory efficiency and speed over absolute accuracy.

## Key Properties
- **False Positives are possible:** It might claim an item is in the set when it actually isn't (due to hash collisions).
- **False Negatives are NOT possible:** If it says an item is *not* in the set, it is 100% definitely not there.

## How It Works
1. **Structure:** It consists of a bit array of size `m` (all initialized to `0`) and `k` different hash functions.
2. **Insertion:** 
   - To add an element, feed it through the `k` hash functions.
   - Each function produces an index number.
   - Set the bit at each of these `k` indices in the array to `1`.
3. **Lookup:** 
   - To check if an element exists, feed it through the same `k` hash functions.
   - If **any** of the resulting indices contain a `0`, the element is definitely NOT in the set.
   - If **all** resulting indices contain a `1`, the element is PROBABLY in the set

# Daily Learning Log: End-to-End RAG (Retrieval-Augmented Generation) Implementation

## 1. RAG Architecture Overview
A RAG system solves the LLM context window limitation and reduces token costs by passing only the most relevant document sections to the model. The pipeline is split into two distinct phases: **Indexing** (ingesting the data) and **Retrieval & Generation** (querying the data).

For this implementation, the stack was optimized for a 100% free, high-performance pipeline:
*   **Framework:** LangChain
*   **Embeddings:** HuggingFace (`all-MiniLM-L6-v2` local model)
*   **Vector Database:** Qdrant (Local Docker container on port 6333)
*   **LLM:** Google Gemini API (`gemini-3.8-flash`)

---

## 2. Phase 1: The Indexing Pipeline
The process of transforming raw PDFs into searchable mathematical vectors.

*   **Document Loading:** Utilized LangChain's `PyPDFLoader` to parse PDFs. The loader reads the file and returns a list where each item represents exactly one page of raw text and its associated metadata (e.g., page number, source file).
*   **Smart Chunking:** Used `RecursiveCharacterTextSplitter`. 
    *   *Chunk Size (e.g., 1000):* Prevents overwhelming the LLM context window.
    *   *Chunk Overlap (e.g., 400):* **Crucial concept.** Creates a deliberate repetition of text at the boundary of two chunks. This acts as a safety net to ensure concepts or sentences split across a mathematical boundary do not lose their semantic meaning.
*   **Vector Embedding:** Swapped paid OpenAI embeddings for `HuggingFaceEmbeddings`. This converts the text chunks into 384-dimensional mathematical arrays locally.
*   **Storage:** Pushed the vectors, raw text payloads, and metadata to a local **Qdrant** database collection (e.g., `learning_rag_hf`).

---

## 3. Phase 2: Retrieval & Generation Flow
The process of converting a user query into an LLM response grounded in the indexed data.

1.  **Query Embedding:** The user's text question is converted into a vector using the exact same HuggingFace model used during indexing.
2.  **Similarity Search:** Qdrant performs a mathematical comparison (Cosine Similarity) between the query vector and the database vectors to extract the top-K most relevant chunks.
3.  **Context Assembly:** The raw text and metadata (page numbers) from the retrieved chunks are formatted into a single context string.
4.  **LLM Generation:** The formatted context is injected into a `SystemPrompt`. The Gemini LLM is instructed to answer the user's query *strictly* based on the provided context and to cite the page numbers.

---

## 4. Database Visualization & Debugging (Qdrant)
The local Qdrant dashboard (`http://localhost:6333/dashboard`) provides critical visibility into the vector space:
*   **Points & Payload:** Verifies the exact number of chunks created and allows inspection of the JSON payload (raw text and metadata) attached to each vector.
*   **Visualize Tab:** Provides a 2D map projection of the 384-dimensional vector space, showing how similar topics naturally cluster together.
*   **Graph Tab:** Displays the HNSW (Hierarchical Navigable Small World) graph connections, visualizing the algorithm Qdrant uses for rapid similarity searches.

### Next Greater Element II: Circular Array & Monotonic Stack

**Core Concept:** Handling circular arrays where elements can wrap around to find the next greater element.

**Two Techniques for Circular Traversal:**

1. **The Offset Method (Brute Force Simulation)**
   * **Formula:** `(i + j) % n`
   * **Mechanism:** Use the current index `i` and an inner loop offset `j` (from `1` to `n-1`). The modulo `n` ensures that if `i + j` exceeds the array bounds, it smoothly wraps back to index `0`. 
   * **Complexity:** $O(n^2)$ time. Good for understanding the modulo wrap-around, but leads to Time Limit Exceeded (TLE) on larger constraints.

2. **Virtual Doubling (Optimized Monotonic Stack)**
   * **Formula:** Loop `i` from `2n - 1` down to `0`, accessing elements via `arr[i % n]`.
   * **Mechanism:** Mathematically simulates concatenating the array to itself (`original + original`). 
   * **Execution:**
      * **Phase 1 (Setup):** Iterating backward through the imaginary second half (`2n-1` down to `n`) pre-fills the monotonic stack with elements from the start of the array.
      * **Phase 2 (Resolution):** Continuing backward into the actual array (`n-1` down to `0`), the stack is already loaded with the wrap-around candidates, allowing standard $O(n)$ Next Greater Element logic to resolve the answers.
   * **Complexity:** $O(n)$ time and $O(n)$ space.

**Implementation (Virtual Doubling):**
```cpp
vector<int> nextGreaterElements(vector<int>& arr) {
    int n = arr.size();
    vector<int> ans(n, -1);
    stack<int> st;
    
    for (int i = 2 * n - 1; i >= 0; i--) {
        while (!st.empty() && st.top() <= arr[i % n]) {
            st.pop();
        }
        if (i < n && !st.empty()) {
            ans[i] = st.top();
        }
        st.push(arr[i % n]);
    }
    
    return ans;
}
