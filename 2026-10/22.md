### 1. Python Virtual Environments & Dependency Management
To prevent system-wide package conflicts, I configured a self-contained Python environment. 

**Key Concepts:**
* **Isolation (`venv`):** Creating an enclosed workspace ensures that project-specific libraries (like `pandas` and `scikit-learn`) do not interfere with global OS dependencies.
* **Reproducibility:** Capturing the exact package state via `pip freeze` allows the environment to be instantly cloned across different machines or production servers. 
* **Path Execution vs. Activation:** Executing a binary directly via its absolute path (e.g., `/root/code/ml-env/bin/jupyter`) automatically utilizes that specific environment's Python engine, bypassing the need for standard activation (`source bin/activate`).

**Workflow Executed:**
```bash
# Initialize the isolated environment using the venv module
python3 -m venv ml-env

# Activate the environment to modify the shell's $PATH
source ml-env/bin/activate

# Install the foundational ML stack
pip install numpy pandas scikit-learn matplotlib

# Snapshot the dependencies for reproducibility
pip freeze > requirements.txt

# Bind to all network interfaces for remote client access
c.ServerApp.ip = '0.0.0.0'

# Listen on the standard Jupyter port
c.ServerApp.port = 8888

# Define the default workspace directory 
c.ServerApp.root_dir = '/root/notebooks/'

# Launch the server utilizing the isolated environment and explicit config
/root/code/ml-env/bin/jupyter lab --config /root/code/jupyter_lab_config.py --allow-root
