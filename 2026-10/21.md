### 💡 Key Learnings

#### 1. Queues in Python (FIFO)
* **Concept:** First-In-First-Out.
* **With Lists:** You can use a standard Python list as a queue by using `.append(item)` to enqueue and `.pop(0)` to dequeue. 
* **Performance Trap:** Using `.pop(0)` on a standard list is **$O(n)$** time because Python has to shift all remaining elements in memory. 
* **Best Practice:** For production, use `collections.deque` which provides `appendleft()` and `popleft()` with **$O(1)$** constant time complexity.

#### 2. Stacks in Python (LIFO)
* **Concept:** Last-In-First-Out.
* **With Lists:** Python lists are perfectly optimized to act as Stacks natively.
* **Methods:** Use `.append(item)` to push, `.pop()` to pop, and `list[-1]` to peek. All of these operate in **$O(1)$** time.
* **Syntax Note:** Unlike other languages (C++, Java), Python lists do not use `.push()` or `.empty()`. To check if a stack is empty, simply use `if not stack:`.

#### 3. LeetCode 678: Valid Parenthesis String
Learned how to handle wildcards (`*`) that can be `(`, `)`, or `""`. Explored two approaches:

* **The Two-Stack Approach ($O(n)$ space):** 
  * Instead of storing characters, store the **indices** of `(` and `*` in two separate stacks.
  * When encountering a `)`, pop from the open stack first. If empty, pop from the star stack.
  * At the end, match remaining `(` with `*`. A `*` can only cancel a `(` if it appears *after* it in the string (`open_index < star_index`).

* **The Greedy Approach ($O(1)$ space):**
  * Tracks a range of possibilities using `min_open` and `max_open`.
  * `max_open` assumes every `*` is a `(`. If it drops below 0, it's an instant failure.
  * `min_open` assumes every `*` is a `)`. If it drops below 0, we reset it to 0 (effectively changing a `*` from a `)` to an empty string `""`).
  * Valid if `min_open == 0` at the end.

### 💻 Code Snippet: Two-Stack Solution for LC 678
```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        openst = []
        starst = []
        
        for i, ch in enumerate(s):
            if ch == "(":
                openst.append(i)
            elif ch == "*":
                starst.append(i)
            elif ch == ")":
                if openst:
                    openst.pop()
                elif starst:
                    starst.pop()
                else: 
                    return False
                    
        # Match remaining left brackets with stars
        while openst and starst:
            if openst[-1] > starst[-1]: # Star is trapped behind the bracket
                return False
            else:
                openst.pop()
                starst.pop()
                
        return len(openst) == 0

### 🧠 Topic: Next Greater Element (NGE) - Monotonic Stacks

#### I. Problem Definition
* **Objective:** Find the first element to the right of each element in an array that is strictly greater than it.
* **Condition:** If no such element exists for a given number, return `-1`.

#### II. Approach 1: Brute Force
* **Logic:** Use a nested loop to iterate through all elements to the right of the current element until a strictly greater value is found.
* **Complexity:** Time **$O(n^2)$**, which is highly inefficient and causes Time Limit Exceeded (TLE) errors for larger datasets.

#### III. Approach 2: Monotonic Stack (Optimized)
* **Logic:** Process the array in a single **backward pass** (from right to left) using a stack to store elements in decreasing order.
* **Intuition (The Light Pole Analogy):** Imagine the array elements as light poles. If you are standing at a current pole looking right, any short poles hiding behind a taller pole are irrelevant. By maintaining a monotonic stack, you actively pop (discard) smaller elements that can no longer serve as the "next greater" for any future elements on the left.
* **Complexity:**
  * **Time:** **$O(N)$** (Specifically $O(2N)$ in the worst case, as every element is pushed and popped from the stack at most exactly once).
  * **Space:** **$O(N)$** (Requires auxiliary memory for the stack and the final result array).
